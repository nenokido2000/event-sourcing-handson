# ユビキタス言語表（倉庫在庫管理）

> この表を **用語の正**とする。コード・ドキュメント・会話で表記を揃える
> （[`.claude/rules/ddd-ubiquitous-language.md`](../.claude/rules/ddd-ubiquitous-language.md)）。
> 由来: [`event-storming/`](event-storming/) の分析成果物。

## 境界づけられたコンテキスト（BC）
| 日本語 | 英名（パッケージ） | 分類 | 中心の集約 |
|---|---|---|---|
| **在庫コンテキスト** | `Inventory` / `inventory` | **コア** | 在庫（`InventoryItem`） |
| 入荷コンテキスト | `Receiving` / `receiving` | 支援 | 入荷（`InboundReceipt`） |
| 出荷コンテキスト | `Fulfillment` / `fulfillment` | 支援 | 出荷（`Shipment`） |
| 棚卸コンテキスト | `Stocktaking` / `stocktaking` | 支援 | 棚卸（`Stocktake`） |
| 受注 / 調達コンテキスト | `Ordering` / `Procurement` | 汎用・外部 | （内製しない。薄い外部トリガ） |

> BC と集約が同名になるのは正常（BC名は領域の中心概念から取られるため）。区別は種別語で行う＝「在庫コンテキスト」「在庫集約」。
> 判定基準は [`event-storming/03-software-design.md`](event-storming/03-software-design.md) の「集約の判定基準」。

## 中核概念（名詞・集約・値オブジェクト）
| 日本語 | 英名（コード） | 種別 | 意味 |
|---|---|---|---|
| 在庫 | `InventoryItem` | 集約（コア） | SKU × ロケーション単位の**残高（手持在庫・引当済）と、それを守る約束**。不変条件 引当可能＝手持在庫−引当済≥0。物そのものではない |
| 入荷 | `InboundReceipt` | 集約 | 受入ドックに届いた、まだロケーション未確定の在庫のかたまり |
| ユニット | （`Sku` の世界） | **集約ではない** | 商品そのもの＝物・数える単位。状態も不変条件も持たない（現場語として記録）。**個体識別しない＝代替可能**（[H13](decisions.md#h13-ユニットを個体識別するか)。壊れる条件もそこに記載） |
| 出荷 | `Shipment` | 集約 | 1注文ぶんの引当を消化して倉庫の外へ出す工程。**引当1件＝明細1件**で複数SKUを持つ（入荷が1SKUなのと非対称。分ける軸が顧客か SKU かの違い）。残高は持たない |
| ~~出荷ステータス~~ | ~~`ShipmentStatus`~~ | 出荷 | **不採用（H15確定）**。進捗（指示済／ピッキング中／出荷済）は明細の累計から導出できるため enum を持たない |
| 棚卸 | `Stocktake` | 集約 | 実地棚卸の**対象ロケーションと終端だけ**を持つ極小の集約。**差異も実地値も持たない**＝実情の把握とレポートに徹する（差異は H10、実地値は [H20](decisions.md#h20-カウントを在庫へ伝えるタイミング)。判断に使わない値は状態に持たない） |
| SKU | `Sku` | 値オブジェクト | 商品識別（Stock Keeping Unit） |
| ロケーション | `LocationId` | 値オブジェクト | 倉庫内の物理ロケーション（棚マス等） |
| 数量 | `Quantity` | 値オブジェクト | 非負整数。加減算・`≥` 比較を持つ |
| 手持在庫 | `onHand` | 状態（`Quantity`） | 物理的に手元にある数量 |
| 引当済 | `allocated` | 状態（`Quantity`） | 予約済み（出荷に向け確保）の数量 |
| 引当可能 | `available` | 導出値（**集約が持つ**） | 手持在庫 − 引当済。引当可能な残り。不変条件 ≥ 0 を守るので集約の中にある。強制点は**引当コマンドの受付ゲート**（棚卸調整だけが例外的に負を持ち込む → H12） |
| 引当ID | `AllocationId` | 値オブジェクト | 引当1件の識別。集約は引当を明細（`AllocationId` → 引当量・払出累計）で持ち、解除・払出はこのIDで指す。**`注文明細ID + ロケーションID` から決定的に導出する**（採番しない。[H26](decisions.md#h26-引当が途中で失敗したときの立て直し)確定） |
| 注文明細ID | `OrderLineId` | 値オブジェクト | 受注BC（外部）が振る注文明細1件の識別。倉庫は採番せず**受け取るだけ**。引当IDの素材になる |
| 払出累計 | `issuedQty` | 状態（`Quantity`） | その引当から棚を離れた数量の累計。**残量を減算せず累計を積む**ので `IssueStock` を累計で受けて冪等にできる（[H30](decisions.md#h30-ポリシーの二重発火にどう備えるか)確定） |
| 数量差分 | `QuantityDelta` | 値オブジェクト | **符号付き**整数。棚卸調整の差分（実地値 − 手持在庫）専用。`StockAdjusted` にのみ現れる |
| 受入量 | `receivedQty` | 状態（`Quantity`） | 入荷でドックに受け入れた数量。受入後は変わらない |
| 格納累計 | `putAwayQty` | 状態（`Quantity`） | その入荷から棚へ上げ終えた数量の累計 |
| 残格納量 | `remaining` | 導出値（**集約が持つ**） | 受入量 − 格納累計。不変条件 ≥ 0 を守るので集約の中にある。**常に非負**（引当可能と違い負を持ち込む経路が無い） |
| クローズ理由 | `ClosureReason` | 値オブジェクト（enum） | 入荷の終わり方。全量格納（`COMPLETED`）／破損（`DAMAGED`）／欠品（`SHORTAGE`）。H14確定 |
| 引当量 | `allocatedQty` | 状態（`Quantity`） | 出荷明細1件が引き当てている数量。出荷指示後は変わらない |
| ピッキング累計 | `pickedQty` | 状態（`Quantity`） | その出荷明細で棚から取り終えた数量の累計 |
| 未ピッキング残 | `remaining` | 導出値（**集約が持つ**） | 引当量 − ピッキング累計。不変条件 ≥ 0 を守るので集約の中にある（残格納量と同じ性質） |
| 出荷完了区分 | `ShipmentCompletion` | 値オブジェクト（enum） | 出荷の終わり方。全量出荷（`COMPLETE`）／欠品を残して完了（`SHORTAGE`）。**人が明示する**（H16確定） |
| 取消理由 | `CancellationReason` | 値オブジェクト（enum） | 出荷の取消理由。注文取消（`ORDER_CANCELLED`）／期限切れ（`EXPIRED`）。H16確定 |
| 解除理由 | `DeallocationReason` | 値オブジェクト（enum） | 引当を解除した理由。注文取消（`ORDER_CANCELLED`）／期限切れ（`EXPIRED`）／欠品出荷（`SHORT_SHIPPED`）。出荷側の語彙を P6 が写像する（H17確定） |
| 凍結中 | `frozen` | 状態（真偽） | 棚卸対象として凍結されている。物理を動かすコマンド（格納・払出）を拒否する。引当は通す |
| 対象ロケーション | `locations` | 状態（`Set<LocationId>`） | 棚卸で回る棚の集合（ゾーン単位。複数可）。開始後は変わらない。棚卸が外から受け取る唯一の情報 |
| 棚卸クローズ理由 | `StocktakeClosureReason` | 値オブジェクト（enum） | 棚卸の終わり方。数え終えた（`COMPLETED`）／中断（`ABORTED`）。**完了区分も人が打つ**（[H21](decisions.md#h21-棚卸の終わらせ方)確定） |
| 実地値 | `countedQuantity` | イベントの値（**状態ではない**） | 棚に実際にあった数量。`StockCounted` に残り、在庫集約と差異ビューが使う。棚卸集約は判断に使わないので保持しない |
| 差異 | `variance` | 導出値（**リードモデル**） | 帳簿値 − 実地値。集約をまたぐ導出値で誰の不変条件も守らないため `StocktakeVarianceView` に置く |

> **英名は日本語の直訳ではなくコード識別子**。揃えるのは**語幹**であって語数ではない。
> 日本語名は会話の語彙で、BC という文脈が効くので短くできる（「在庫コンテキストの在庫」）。
> クラス名にはその文脈を補う場所がパッケージしかないため、**BC名と語幹が被る集約（在庫・入荷）には限定語を付ける**
> ＝ 在庫 → `InventoryItem`（`inventory.Inventory` では SKU×ロケーション1件という粒度が読めない）／入荷 → `InboundReceipt`。
> 語幹が被らない出荷（`Shipment`）・棚卸（`Stocktake`）が1語で済むのはこのため。日英で語数が違うのは用語のブレではない。

## コマンド（命令形の動詞）
| 日本語 | 英名 | 対象集約 | 意味 |
|---|---|---|---|
| 入荷する | `ReceiveStock` | 入荷 | 受入ドックに在庫を受け入れる |
| ~~検品する~~ | ~~`InspectStock`~~ | 入荷 | **不採用（H8確定）**。検品は入荷〜格納に内包し、独立したコマンドにしない |
| 格納する | `PutAwayStock` | 入荷 | ロケーションを選定して格納する（分割格納可） |
| 入荷をクローズする | `CloseInboundReceipt` | 入荷 | 破損・欠品で残格納量を残したまま入荷を終える（H14確定。全量格納時の完了は自動発行） |
| 在庫を計上する | `PlaceStock` | 在庫 | 格納の結果、在庫へ手持在庫を加える（ポリシーP1） |
| 引き当てる | `AllocateStock` | 在庫 | 引当可能の範囲で在庫を予約する |
| 引当を解除する | `DeallocateStock` | 在庫 | 予約を取り消す |
| 出荷を指示する | `RequestShipment` | 出荷 | 出荷を要求（薄い外部トリガ・注文単位。H9確定） |
| ピッキングする | `PickStock` | 出荷 | 棚から取り出す |
| 在庫を払い出す | `IssueStock` | 在庫 | ピッキングの結果、手持在庫・引当済を減らす（ポリシーP3・H7確定） |
| 出荷する | `ShipStock` | 出荷 | 出荷を完了する。**完了区分（全量出荷／欠品）を人が明示する**（H16確定） |
| 出荷を取り消す | `CancelShipment` | 出荷 | ピッキング前の出荷を畳む（注文取消・期限切れ）。1件でもピッキング済みなら拒否（H16確定） |
| 棚卸を開始する | `StartStocktake` | 棚卸 | 対象ロケーション（**複数可**・ゾーン単位）を確定し棚卸を始める（循環棚卸）。→ P5 が凍結 |
| カウントする | `CountStock` | 棚卸 | 実地数量を記録する。**数量ゼロ可**（棚に何も無かった）・**数え直し可**（最新が正）・**帳簿に無いSKUも可**（[H18](decisions.md#h18-棚卸は数える対象の母集合を持つか)確定） |
| 棚卸をクローズする | `CloseStocktake` | 棚卸 | 棚卸を終える。**数え終えた／中断を人が明示する**（[H21](decisions.md#h21-棚卸の終わらせ方)確定。再開はできない）。→ P5 が解凍 |
| 在庫を調整する | `AdjustStock` | 在庫 | **実地値（絶対値）**を渡して在庫を実情へ合わせる。差分は在庫集約が出す（ポリシーP4・H10確定） |
| 凍結する | `FreezeStock` | 在庫 | 棚卸対象として凍結する（サーガP5） |
| 解凍する | `UnfreezeStock` | 在庫 | 棚卸終了で通常運用へ戻す（サーガP5） |

> **「在庫」はBCによって意味が変わる**（多義性はBCが吸収する＝正常）。
> 入荷コンテキストの「在庫」＝受入ドックの荷物（まだ引けない）／在庫コンテキストの「在庫」＝棚の残高（引当可能かが全て）／
> 出荷コンテキストの「在庫」＝棚から取り出された物理の在庫。イベント名が `Stock*` で揃っているのは可読性のためで、
> 主語の意味は所属BCで読む。

## イベント（過去形・完了した事実）
| 日本語 | 英名 | 発生集約 | 意味 |
|---|---|---|---|
| 受注が受け付けられた | `OrderAccepted` | 外部・受注 | 注文が成立した（薄い外部トリガ・明細のリストを持つ）。**引当ポリシー P2 の入力**。引当は受注成立**後**の倉庫作業（[H24](decisions.md#h24-引当は受注の前か後か)確定） |
| 在庫が入荷された | `StockReceived` | 入荷 | 受入ドックに在庫が届いた（ロケーション未確定・引当不可） |
| ~~在庫が検品された~~ | ~~`StockInspected`~~ | 入荷 | **不採用（H8確定）**。検品は入荷〜格納に内包する |
| 在庫が格納された | `StockPutAway` | 入荷 | ロケーションが確定し入荷集約から引き落とされた |
| 入荷がクローズされた | `InboundReceiptClosed` | 入荷 | 入荷が終わった。**残格納量＋クローズ理由**（全量格納 / 破損 / 欠品）を持つ（H14確定） |
| 在庫が計上された | `StockPlaced` | 在庫 | 在庫に手持在庫が加わり引当可能化した |
| 在庫が引き当てられた | `StockAllocated` | 在庫 | 引当可能から予約が確保された |
| 引当が解除された | `StockDeallocated` | 在庫 | 予約が取り消された |
| 出荷が指示された | `ShipmentRequested` | 外部・出荷 | 出荷が要求された（薄い外部トリガ・注文単位。H9確定） |
| 在庫がピッキングされた | `StockPicked` | 出荷 | 棚から取り出された |
| 在庫が払い出された | `StockIssued` | 在庫 | 手持在庫↓・引当済↓（同額ずつ減るので引当可能は不変）。受払の「払出」側 |
| 在庫が出荷された | `StockShipped` | 出荷 | 出荷が完了した（残高はピッキング時に確定済み）。**出荷実績明細＋完了区分**を持つ（H16確定）。明細は1件＝1行で**出た量と残った量を同じ行に持つ**（[H44](decisions.md#h44-出荷イベントが持つ明細の形)確定） |
| 出荷が取り消された | `ShipmentCancelled` | 出荷 | ピッキング前の出荷が畳まれた。**取消明細＋取消理由**を持つ。出荷とは別の事実（物は倉庫を出ていない。H16確定） |
| 棚卸が開始された | `StocktakeStarted` | 棚卸 | 棚卸の対象ロケーション（複数可）が確定した |
| 実地数量がカウントされた | `StockCounted` | 棚卸 | 実地数量が記録された（棚卸が持つ事実はここまで。差異は持たない）。P4 が**都度**在庫へ伝える（[H20](decisions.md#h20-カウントを在庫へ伝えるタイミング)確定） |
| 棚卸がクローズされた | `StocktakeClosed` | 棚卸 | 棚卸が終わった。**クローズ理由**（数え終えた / 中断）を持つ（H21確定） |
| 在庫が凍結された | `StockFrozen` | 在庫 | 棚卸対象になった（以降 格納・払出を拒否／引当は通す） |
| 在庫が解凍された | `StockUnfrozen` | 在庫 | 通常運用へ戻った |
| 在庫が調整された | `StockAdjusted` | 在庫 | 手持在庫が実情へ補正された。**符号付き差分＋実地値＋原因（`StocktakeId`）**を持つ補正イベント（H10確定） |
| 在庫がロケーション間で移動された | `StockMoved` ❓ | 在庫 | 別ロケーションへ移動した（M3+改修候補・H5） |

## ポリシー / リードモデル
| 日本語 | 英名 | 種別 | 意味 |
|---|---|---|---|
| 格納伝播ポリシー | `PutawayPolicy`（P1） | ポリシー（状態なし） | 在庫が格納された→在庫を計上する。入荷集約→在庫集約 |
| 引当ポリシー | `AllocationPolicy`（P2） | ポリシー（コア・状態なし） | 受注→引当可能在庫ビュー参照→引当先選定→引き当てる。棚卸中ロケーションは後回し（H11） |
| 出庫反映ポリシー | `FulfillmentPolicy`（P3） | ポリシー（状態なし） | 在庫がピッキングされた→在庫を払い出す。出荷集約→在庫集約（P1と対称の出口側） |
| 棚卸反映ポリシー | `StocktakePolicy`（P4） | ポリシー（状態なし） | 実地数量がカウントされた→在庫を調整する。実情を在庫へ伝えるだけ（差異計算はしない） |
| 棚卸凍結サーガ | `StocktakeFreezeSaga`（P5） | **Saga（状態あり）** | 棚卸開始→対象在庫を1件ずつ凍結／クローズ→解凍。**本PoCで唯一の Saga** |
| 引当解放ポリシー | `AllocationReleasePolicy`（P6） | ポリシー（状態なし） | 出荷が欠品で完了／取り消された→残った引当を解除する。出荷集約→在庫集約。**残明細の数だけ送る 1:N だが状態を持たない**（H17確定） |
| 引当可能在庫ビュー | `AvailableStockView` | リードモデル | SKU×ロケーション別の引当可能数（＋棚卸中フラグ） |
| 引当ビュー | `AllocationView` | リードモデル | 引当の一覧（出荷・取消の入力） |
| 在庫元帳ビュー | `StockLedgerView` | リードモデル | 全在庫変動の履歴（ES の履歴の旨味を可視化） |
| 棚卸差異ビュー | `StocktakeVarianceView` | リードモデル | 実地値と調整差分を突き合わせた棚卸レポート（差異＝集約をまたぐ導出値なのでここに置く） |
| 棚卸干渉ビュー | `StocktakeInterferenceView` | リードモデル | 凍結中を理由に在庫へ反映できなかった作業の一覧。人が「再投入」か「破棄」かを判断する（H22確定） |

> **語尾の約束**: 状態を持たない伝播＝`...Policy`、状態を持つ長期プロセス＝`...Saga`。
> 分ける基準は**状態の有無**であって fan-out の有無ではない（P6 は 1:N だが状態なし＝ Policy / H17）。
> 実装（`@EventHandler` か Axon の Saga か）と1対1で対応する。導出は [`event-storming/02-process.md`](event-storming/02-process.md)。

## 参考用語

**このモデルには存在しない**が、議論や ADR に出てくる外部の業界用語。表記のブレを防ぐため
ここで日本語名を固定する。**コードには現れない**（上の表と違い、英名は識別子ではなく元の用語）。

| 日本語 | 元の用語 | 意味 | 本PoCでの扱い |
|---|---|---|---|
| 受注可能量 | ATP（Available To Promise） | 「今この注文を受けたら約束どおり出荷できるか」に答えるための数。既に他の注文へ約束済みの分を差し引いた、**これから約束に使える残り**。SCM 由来 | **採らない**。引当は受注成立後の倉庫作業（[H24](decisions.md#h24-引当は受注の前か後か)）。M3+ 改修シナリオ候補として温存 |
| 販売枠 | allotment / quota | 倉庫が販売チャネルへ配る「ここまで売ってよい」数。**配られた側が自分で減らす**（数の所有権が移る） | **採らない**。受注BCを内製しないため（[H9](decisions.md#h9-出荷指示の出所と粒度)）。受注可能量を実現する方式の本命として H24 に記録 |

> **「引当可能」と混同しない**。ATP の訳語のひとつ「引当可能在庫量」は、本PoCの
> **引当可能＝手持在庫 − 引当済**（中核概念表）と字面が衝突する。英語も `available` が両方に出る。
> このため日本語名を**受注可能量**に固定し、会話・図・ADR ではこちらを使う（`ATP` は初出時の併記に留める）。
