# ドキュメント整合

`docs/` は肥大化していくため、**手で書いた値が他所とズレる**のが最大の腐り方。
構造で防げるものは構造で、機械で検出できるものは `scripts/check-docs.py` で守る。

## 書くときの約束

- **他所から導出できる値を書かない**。集計値（「ポリシーは5本」「集約4つ」）や採番（「次は H13〜」）を
  そのまま書くと、増えたときに必ず腐る。**数を書かず、一覧表や定義元へリンクする**。
  - 例外: **その時点の事実として記録する場合**は書いてよい（ADR の「5本 → 6本になる」、
    README の「M1 で P1〜P5 を確定」など、過去の記録は更新されなくて正しい）。
- **同じ情報を2か所に持たない**。片方が必ず更新漏れになる。
  - M2 のスライス進捗の正は [`docs/tactical-design.md`](../../docs/tactical-design.md) の冒頭表。
    ルート `README.md` はマイルストーン粒度（M0〜M8）までにして、リンクで渡す。
  - 決定の正は [`docs/decisions.md`](../../docs/decisions.md) だけ（他は結果を書いてリンク）。
- **見出しを変えたらアンカーが切れる**。`decisions.md` の H見出しは他文書から広く参照されている。

## 新しい概念を足したときの波及先

集約・ポリシー・イベントを新設したら、以下に反映されているか確認する（機械では意味まで見られない）。

| 足したもの | 波及先 |
|---|---|
| 集約 | `ubiquitous-language.md` / `context-map.md` / `tactical-design.md` / `event-storming/03-software-design.md` |
| ポリシー | 上記に加えて `event-storming/02-process.md`（M1 の記録なので**書き換えず注記**を足す） |
| イベント・コマンド | `ubiquitous-language.md` / `tactical-design.md` |
| 決定 | `decisions.md`（本文＋**一覧表の行**）。他文書は結果だけ書いてリンク |

**`event-storming/` は M1 時点の分析記録**なので、後から決まったことで書き換えない。
結論が変わった場合は「M2 で〜になった」という注記とリンクを足す（記録としての価値を壊さない）。

## 機械チェック（`scripts/check-docs.py`）

pre-commit と Stop フックで自動実行される。手動なら `python3 scripts/check-docs.py`。

見るもの（決定的に判定できるものだけ）:

1. `decisions.md` の `## Hn` 見出しと一覧表の行が集合として一致するか（欠番・重複・片側漏れ）
2. `](file.md#anchor)` のアンカーが実在する見出しに解決するか
3. `ubiquitous-language.md` で定義したポリシー番号が波及先文書に現れるか／未定義の番号を参照していないか

**見ないもの**: 意味の矛盾（決定Aと既存記述Bが噛み合わない）。これはレビューの仕事で、
`es-domain-reviewer` と人が読むことでしか捕まらない。チェックが通ったことは正しさの証明ではない。
